# Independent grader and reference admission

This package runs only in the trusted evaluation service. Do not register it as a worker tool or package it into a worker/candidate image. The independently constructed hidden manifest is its authority; primary correctness uses exact deterministic comparisons and no model judge.

`referenceSolve(world, bounds?)` scans visible schema/evidence, resolves exact identity/aliases from the authorized subject, traverses declared reference fields under bounded hops, and returns a typed `ReferencePlan`. `runReference(world, bounds?)` applies the plan to a clone. This exhaustive reference procedure is separate from the runtime discovery implementation and the oracle's independent intent recipe. It is admission tooling, not an expert worker bypassing the actual primitive tools/model.

`admitWorld(spec, seed, binding?: ScopeKey)` validates Hider input, generates private truth and requires the visible reference solution to match every expected effect and preservation obligation within bounds, and runs the shape-only detectors from `@expunge/fixtures/sealed`: a world whose targets are identifiable by record shape better than chance is quarantined with `shape_leak` (plus `shape_leak:<detector>`). Unsafe, impossible or inconsistent recipes return quarantine reason codes (bound violations such as `document_bound`, `hop_bound`, `six_unique_collections`; malformed input is `malformed_spec`); a native runtime error is reported as `internal_error` rather than disguised as a bad spec, and error text is never echoed. The admitted result contains a sealed fixture for trusted seeding only. Return `publicAdmissionVerdict(result)` to Hider/proposer tools; it strips all answer-bearing state. Its `referenceResultHash` is computed from public fields only (spec hash, solver hash and the public grade hash), never from the private grade `reportHash`, which covers the manifest and expected-poststate hashes.

`gradeWorld(manifest, actualWorld, evidence)` binds world/spec/manifest hashes, independently sealed ScopeKey/revision, complete scope-registry/schema commitments and subject handle. It also rejects document tenant/environment/world mismatches. It reports target residuals, collateral changes, preservation/retention violations, refusal/retry outcomes and truthful terminal status separately. Preservation hashes cover the business, display-name and eligibility fields of every rewritten target, the whole record of a restricted target, and each unrelated element of a mixed wildcard array by concrete position, so deleting an array wholesale or rewriting a neighbour is a preservation violation. Evidence is validated at runtime (`terminalStatus`, `terminalClaim`, `retryFailures`). `publicGradeReport(report)` is the only view that may leave the evaluator: it withholds `manifestHash`, `actualStateHash`, `expectedStateHash` and `reportHash` (a poststate hash would be an offline answer-check oracle) and carries a `publicReportHash` over the public fields only. Useful completion requires the correct poststate, preservation, no required retry failure and truthful completion. A blanket delete or refusal cannot pass.

`GradeEvidence.terminalStatus` is `complete|incomplete|refused`. The default `terminalClaim=all_targets` grades unqualified baseline success strictly. For a scoped receipt claim, pass `terminalClaim=registered_scope` and `trustedReceiptEvidence={receipt, binding, currentWorldRevision, committedReceiptHash}`. `binding` is the stored `RunBinding`; the hash is `contentHash(receipt, 'completion-receipt')`. These values must be read/verified by the trusted service from committed authority state, never accepted from model text. The grader checks receipt hash, run/job/harness/world/scope/revision bindings, exact registered collection and field coverage with no missing/duplicate/unknown IDs, zero operational residuals and every sealed discovery limitation. Missing coverage cannot be justified by a generic limitation string. It does not mint or prove issuance of a receipt. A valid scoped statement can be truthful while a hidden copy causes useful completion to fail; that trial requires an explicit trusted partial observation sealed before execution. The runtime/gateway remains responsible for stable-sweep and committed-issuer proof.

`FaultSession` and `runReferenceWithFaults` are labeled local simulators. They inject transient pre-commit errors, batch interruption and lost post-commit acknowledgements deterministically, keep logical effect keys/digests stable, replay exact receipts and reject changed arguments. They establish deterministic fixture behavior, not live Atlas write fencing or crash durability. Runtime integration must implement the Mongo transaction protocol independently.

Generator, reference-solver, evaluator and split-builder hashes include actual implementation bytes and canonical hash code (including `packages/contracts/src/index.ts`). Grade reports and manifests pin these commitments. No private seed enters a public hash preimage export. Recompute/freeze campaign commitments whenever implementation changes.

Sources followed: the frozen Expunge contracts, data model, source map and acceptance protocol. `reference.ts` is a new slow exact traversal, `sealed.ts` uses independent recipe intent, and `grade.ts` compares independently frozen poststates/preservation hashes. No vendor calls, network access, external account mutation or publishing occur here.

Tests (`packages/grader/test`): `grader` and `faults` (admission of all families and 42 split worlds, fault simulation), `protections` (wrong poststates, blanket delete/redact/tombstone/refusal, retention corruption, fabricated and forged completion, scope/tenant/env/world binding, trusted partial observation), `wildcard` (registry grammar and mixed-array preservation end to end), `canary` (a real scan of public outputs and error messages against private manifest values, with positive controls), `admission` (bounds and quarantine without crashes) and `admission-shape` (the `shape_leak` quarantine, using a labelled test double).

Remaining integration evidence: independent service/principal and image-content denial, actual Atlas fixture seeding/readback, live gateway execution, operational receipt transaction/revision proof, Hider campaign integration, paired worker trials, remote traces and final benchmark export. Local tests do not claim these have run.
