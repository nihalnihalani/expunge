# Expunge Verification and Demonstration

This is the verification specification for the full implementation now being built. Check completion against the actual commands, receipts and build reports; the presence of a checklist is not a passing result. Source inspection and deterministic local checks remain separate from live service verification.

## Full scope feature matrix

| Feature | Evidence needed before claiming it works |
|---|---|
| OpenDots operator shell | Real authenticated conversation/job, review card and reconnect against chosen runtime. |
| OpenBot execution | A real per-Dot computer action through the existing supervisor with separate credentials and no private data/keys. |
| OpenMuse runtime reuse | Attributed wrapper/helper code used in the actual worker path; pinned provider/typecheck/state/clone checks. |
| Deep Atlas domain | Cleanup actually changes registered collections and preserves unrelated documents. |
| Four editable harness surfaces | A typed version for context/workflow/guardrail/tool access and at least one exercised change in each surface across recorded generations. |
| Executable source adaptation | If claimed, an actual candidate plugin runs inside the restricted sandbox behind the same gateway; a text-only diff is insufficient. |
| Raindrop worker/improver tracing | Real linked events with version/job identity and tool/model evidence read back remotely. |
| Raindrop-driven incident loop | The observer uses retrieved remote content in a proposal; origin labels and causal-control comparison retained. |
| Historical replay | Recorded actions re-evaluated against as-of facts; results explicitly labeled decision replay. |
| Fresh admission | Reset-world parent/candidate outcomes, fixed independent truth and protected cases. |
| Authority governance | Independently classified widening, trusted stored review, exact scope/hash binding and one consumed grant. |
| Atomic promotion/rollback | Real same-parent race, pointer/receipt consistency and new-run version pin. |
| Durable execution | Crash/reclaim before and after commit with no repeated logical Mongo effects. |
| Adversarial curriculum | An admitted Hider-generated hard layout, reference-solver proof and measured worker outcome. |
| Improved improver | Fresh W0/I0 versus W0/I1 produced-worker comparison, equal budget and noise/control results. Null is acceptable; unsupported gain is not. |
| Privacy lifecycle | Revoked sources excluded from new contexts; retained artifact bytes checked; external request/purge states accurately represented. |
| Deployed product | Real host topology, auth/origins, server-only secrets, health checks and accessible demonstration. |

The build includes all these lanes. A feature that is still waiting on a service permission or failed check stays visibly incomplete; a replay or mock never substitutes for evidence of a live claim.

## Scientific protocol

Freeze before evolution: worker/provider/model parameters, runtime adapter hash, baseline/expert bundles, generator/reference/evaluator hashes, split commitments, budgets, fault definitions and admission thresholds. Record the exact provider model used; do not rely on model names inherited from old notes.

Use this **proposed initial configuration**, frozen in a campaign manifest after provider/Atlas timing probes. These are planned counts/bounds, not measured results. A changed configuration creates a new campaign hash and is disclosed before running final evaluation.

| Configuration | Initial value |
|---|---|
| Controlled world | At most 500 domain documents, six collections, five reference hops; fixture generator must satisfy these bounds. |
| Worker execution | At most 12 model/tool phases each, 120 seconds per episode, 24,000 total token cap; document/effect caps from owner scope. |
| Parallel episodes | Start with four; raise to eight only after provider-rate and Atlas-ops probes support it. |
| Candidate mutation | At most three independently justified edits; no authority increase without a bound grant. |
| Training trigger evidence | Two distinct structural failure worlds, three repeats each per parent/candidate. |
| Protected gate | Eight legitimate/preservation/retry worlds, two repeats each per parent/candidate. |
| Validation gate | Eight separate structural worlds, two repeats each per parent/candidate; raw answers withheld from proposer. |
| Promotion utility | Candidate gains at least two successful outcomes among the six paired trigger runs; no candidate preservation/retention violation in the gate; no protected-case success count below its paired parent; aggregate validation success count does not fall. |
| Final test | 24 structurally held-out worlds, three repeats, five conditions: 360 task episodes. No tuning on this output. |
| Meta comparison | Eight new incidents, reset W0 for I0 and I1; at most three proposals/equal token budget per improver; each produced worker tested on three further worlds with two repeats. Add I0/I0 and no-data controls with predeclared matching budgets. |
| Hider | Twelve admitted new WorldSpecs across the frozen structural families; retain quarantined proposals and reasons. |
| Cost admission | Set a measured predeclared cost/latency ceiling after baseline probes; token and call ceilings always enforced. Unknown pricing is reported and cannot silently satisfy a dollar-based gate. |

The candidate gate uses paired cases, not a population-level guarantee. The final 360-episode estimate is a compute-planning input; record actual executed counts/failures/timeouts. Service capacity can change concurrency and batch schedule without changing the feature scope or hiding unfinished trials. Show progress/completion honestly. All numeric bounds are trusted executor/gate settings, not editable model self-reports.

For the task-agent experiment, run initial harness, expert-static harness, evolved harness, score-only evolution and wrong-incident evolution. Pair worlds/seeds across arms; repeat stochastic executions with the same sampling policy. Separate development/train, gate-validation/protected and final test splits. Evolution sees training evidence and at most scalar/structured gate verdicts; final test is scored after the frozen version is chosen.

Task success is correct target effects **and** preservation **and** truthful terminal status. Keep separate counts for residuals, collateral changes, wrong retention effects, false refusals, necessary retry failures, tool/model calls, tokens, dollars and wall time. Count observer/improver and amortize improvement cost over disclosed task volume. Record all rejected/failed candidates. Report paired counts/raw rows and uncertainty appropriate to sample size; no universal zero-risk conclusion from a small suite.

Structural test families:

1. Direct plus nested-array paths with new field names.
2. Subject→account→event composition with new aliases.
3. Cycle/duplicate references plus disconnected namesake.
4. Mixed eligibility requiring delete/redact/restrict/tombstone.
5. Partial acknowledgement/interrupted batch and retry.
6. A composition of separately learned structures in an unseen layout.

The expert-static procedure is essential. A learned archive/receipt rule may be a rediscovered obvious invariant. A tie with expert-static is reported as a tie, while reduced configuration effort or adaptation latency is measured separately.

Each retained edit must have standing: source incident, raw trace evidence, hypothesis, actual changed artifact, trigger effect and protected-case outcome. A wrong-incident or score-only patch that achieves the same improvement weakens a claim that trace information caused the gain. Preserve that result.

Historical replay answers how a candidate policy treats recorded decisions. It cannot answer what a new agent would do. Fresh trial reruns are mandatory. The replay's as-of facts must not include outcomes/receipts unavailable when that recorded decision was made.

Meta experiment: reset identical W0 for I0 and I1, give equal new-incident evidence/budgets, then score the workers each produces on separate fresh test worlds. Include I0/I0 noise and no-data rewrite controls. Do not carry I1's prior worker memory/artifacts into the new base. Treat the incident/produced-worker pair as the unit. Publish null/negative results.

Hider experiment: admit proposed layouts only when the fixed reference solver succeeds under the same resource/eligibility rules. Reward admitted challenge difficulty, not impossible tasks. The Hider cannot change scoring, private expected poststates or world safety bounds.

## Three minute demonstration

The displayed counts below are filled from measured outcomes. They are not targets masquerading as results.

| Time | Action | Evidence visible |
|---|---|---|
| 0:00–0:25 | Start/replay a real baseline cleanup in a seeded synthetic company. | Actual model output, surviving reference and protected-record state. Identify replay if used. |
| 0:25–0:50 | Open linked Raindrop worker trace. | Real remote event/span IDs and failure origin; improver evidence packet. |
| 0:50–1:30 | Propose and test a new harness while explaining one changed mechanism. | Actual diff, paired trial rows, rejected unsafe candidate and declared coverage. |
| 1:30–1:55 | Show committed promotion and tool/workflow change. | Parent/child hash, promotion receipt, grant when required; no client-only badge. |
| 1:55–2:30 | Run new synthetic subject/layout using the same model. | Residual/preservation result and committed completion receipt. |

Keep source/role/replay/approval details accessible in Q&A rather than adding stage beats. The operator can select a genuinely recorded generation if a live candidate is slow; label that selection. Never fake remote evidence readiness or swap in a scripted success while calling it a model run.
